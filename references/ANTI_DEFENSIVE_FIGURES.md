# 科研插图的正向叙事、反防御性与反小字声明指导

日期：2026-10-16。适用对象：论文中的方法图、技术路线图、图内标注、标题与 caption。

本文件根据用户指定的 anti-defensive-writing 写作原则 改写，形成面向科研插图的项目执行指南。源 skill 的核心原则是：“论文是一场学术发布会，不是项目总结、实验日志或自我审查报告。”本指南将这一原则落实到图的主线、标注与视觉层次。

## 1. 图首先展示成立的机制与价值

绘图前写一句主旨：读者看完应理解哪个机制、能力或结果？围绕这句话安排模块、箭头、阶段与证据。图内文字优先回答三个问题：对象是什么、承担什么作用、如何产生结果。

例如，SID 方法图的主线是：内容表示形成语义前缀，消歧 token 建立唯一物品映射，序列模型生成 SID 完成推荐。三段围绕这一机制展开，主线标签优先使用 Content tokenization、Unique item mapping、Generative recommendation。

## 2. 用正面定义替换预先辩解

遇到否定句，先识别它希望澄清的事实，再把事实写成对象、功能或阶段标签。

| 原标注 | 保留的科学信息 | 建议表达 |
|---|---|---|
| Final token ≠ RQ level. | 最后一个 token 承担碰撞消歧职责 | Item disambiguation token |
| Reconstruction during tokenizer training only | 重建分支用于 tokenizer 的训练 | Tokenizer reconstruction objective |
| Shared prefixes encode learned semantics; they do not guarantee ground-truth categories. | 前缀承载学习到的物品语义 | 移入正文：Shared prefixes encode learned item semantics. |
| Not used for retrieval | 模块归属于 tokenizer 训练阶段 | Tokenizer training branch |
| This is not an attention mechanism | FiLM 通过逐通道仿射变换执行条件化 | Channel-wise affine conditioning |
| No separate codebooks at each depth | 经典图像 RQ-VAE 跨深度共享码本 | Shared codebook across depths |
| Only one spatial location is shown | 局部面板展开单个位置的计算 | Quantization at each spatial location |

改写应保存原句中的有效信息。训练分支的阶段归属由面板标题和分支名称表达；共享码本通过同一码本向多个深度的连线表达。机制解释与适用条件在正文中展开。

## 3. 反小字声明：解释说明放在正文

**图中不要放解释性的小字声明。关于方法含义、设计原因、适用范围、例外、限制或读者可能误解之处的解释，放到论文正文中。**

这一要求按文字的功能判断。把声明改成肯定句、换成灰色、挪到图的底部或加大字号，都不能替代对其位置的判断。例如，`Shared prefixes encode learned item semantics.` 虽然采用正面表达，作为图底说明句仍应移入正文。

图内保留直接参与解码图形的信息：模块名称、输入输出、变量与维度、核心公式、算子、箭头或线型的必要图例、坐标与单位、简短阶段标签。文字紧邻它标识的对象，使用与同层级标签一致的可读字号。

| 内容 | 处理方式 |
|---|---|
| Item disambiguation token | 作为对象名称贴近末尾 token，必要时用短引线连接 |
| Tokenizer training | 作为阶段标签，与相应模块分组对应 |
| Shared codebook | 作为码本名称，通过连线表达跨深度共享 |
| 关于语义前缀含义或类别保证的整句说明 | 移入正文，结合方法定义解释 |
| 关于示意、适用范围、例外或读者误解的补充声明 | 移入正文的相关方法或实验段落 |
| 为填补连线、模块分组或符号关系不清而追加的说明句 | 先修正图形结构，再由正文展开机制解释 |

图中留白服务于阅读、分组与层次。正文解释与图形表达分工明确；caption 简要说明图的主题、子图对应关系和必要符号。解释性声明优先归入正文，不能默认搬到 caption 中继续堆积。

## 4. 按职责分配图、图注与正文

- **主图**：呈现关键对象、数据流、算子与主要结果。
- **局部面板**：以图形、核心公式与简短标签展开关键机制，如 FiLM 的乘加操作或残差量化的逐深度更新。
- **caption**：简要说明图的主题、子图对应关系和必要符号。
- **正文**：解释机制、设计理由、例值含义、适用条件和结果分析，承接从图中移出的说明性文字。
- **制作记录**：保存字体、矢量检查、版本、模板编译和重建信息。

读者首先看到方法如何工作。科学适用条件在相关位置准确交代；制作与验收信息保存在独立交付记录中。

## 5. 视觉结构也承担正向叙事

1. 把核心机制放在清晰的主路径，辅助训练分支与主路径保持可辨认的层级。
2. 将标签放在它定义的对象旁边。SID 的前缀标注靠近前缀，消歧标签用短引线指向最后一个 token。
3. 共享、求和、残差、条件化等关系通过真实连接表达，减少依靠说明句补救结构。
4. 标注使用短而具体的名词或动词，如 Shared codebook、Selected vectors、Generate SID、Retrieve item。
5. 描述优势时给出实际机制或证据。例如“Unique item mapping”由完整 SID 到不同物品的实例映射支持。

## 6. 判断表达功能，保留科学含义

检索 `only`、`not`、`do not`、`cannot`、`≠`、“仅”“不是”“不等于”等，可帮助发现预先辩解。每个命中项都结合语义判断。

算法定义中的不等式、约束条件、对照组名称和真实实验结果按其科学含义保留。例如 $r_d\ne 0$ 若属于停止条件，应作为算法条件表达。`only` 若传达关键阶段信息，应将阶段写成明确标签，而不是删除事实。

图与 caption 的主张始终与方法、数据和证据一致。实验比较沿用已确定的口径，结果与版本记录完整保存。反防御性改写提升表达的方向与重点，不改变计算关系或证据。

## 7. 图内标注的逐项改写流程

1. 提取图中的全部标题、标签、脚注与 caption。
2. 给每句话标注职责：机制、对象、阶段、价值、示例或制作说明。
3. 找出预先回应误读、预设质疑或重复解释的句子。
4. 将对象职责改写为简短正面标签，用模块分组和连线表达关系；将整句解释与声明移入正文。
5. 检查主线是否更集中，模块职责与训练／推理关系是否仍然准确。
6. 在最终尺寸检查标签位置、视觉层次与可读性。

## 8. 交付前检查

- [ ] 图的主旨能用一句话说清，主路径围绕该主旨组织。
- [ ] 关键标签直接说明对象、操作、阶段或结果。
- [ ] 碰撞消歧、共享码本、辅助重建等信息通过正面定义与真实结构表达。
- [ ] 各类条件、约束、例值和数学关系保留完整科学含义。
- [ ] 图中没有解释性小字声明；图底、空白区和边角保留清晰留白。
- [ ] 肯定句也已按功能审查，整句机制解释与声明已移入正文。
- [ ] 必要标签、图例和核心公式在最终尺寸下可读。
- [ ] caption 简洁定位图与子图，正文承接解释说明，制作记录独立保存。
- [ ] 图内主张与所给方法及证据一致，版本和实验记录可追溯。
