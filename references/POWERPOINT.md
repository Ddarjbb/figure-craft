# SVG 与原生 PowerPoint 的编辑交付

适用：制作 SVG、修复 SVG 在 PPT 中的数学符号缺失，以及用户明确要求原生 PPT 的任务。交付范围先按 `SKILL.md` 的格式路由确定。本文件不因提到 PPT 而自动要求生成 PPTX。

## 1. 交付 SVG 时

- 普通标题和标签保留为 `<text>`，保留字体、字号、基线、颜色；不默认全部转曲。只有用户明确要求文字转曲、固定跨机字形或相关实测故障时，才处理普通文字轮廓。
- 数学符号继续由 LaTeX、MathJax 或同等引擎排版；“保留普通文字”不表示把数学符号改成普通文本。
- 原本已是矢量的公式也可能通过 `<defs>` / `<use>` 引用字形。将这些引用展开为直接绘制的路径，并统一 SVG 命名空间；仅把文本转曲而保留有问题的引用，不足以解决公式导入缺失。
- 每条公式尽量合并为一个复合路径，包括上下标、分式横线等；在保持填充、笔画、孔洞与变换正确的前提下合并。不同颜色或特殊笔画不能无条件拼成同色路径，必要时保留为少量路径组成的公式组。
- 保持矢量；不能以整图 PNG 嵌入 SVG 的方式解决兼容性。
- 给一个经过验证的最终 SVG。中间稿、全部转曲备份和其他兼容变体保留在构建目录，不主动多交付。

### 按语义分组

在画源稿时定义分组，避免导出后用坐标猜测归属。层级按内容决定，不固定模块数量：

```text
整图
  模块
    节点 + 其标签
    矩阵（可再分行块，内部单元格可选）
    向量
    箭头（线与箭头尖成组）
    一整条公式
```

使用有意义的组名。保持绘制顺序，不因重排组而把边线盖到节点之上。避免把每个字母或每个矩阵格都作为顶层操作对象。

### 可复用导出辅助工具

`scripts/prepare_ppt_svg.py` 用于本 skill 数学渲染器生成的普通矢量结构图：保留普通文本和既有语义组，展开本地字形引用，并合并 `data-latex` 公式组。它不推断语义组、不生成 PPT/PDF/PNG，也不改写输入文件。

```text
python scripts/prepare_ppt_svg.py --input build/figure-source.svg --output figure.svg --report build/svg-check.json
```

依赖 `fontTools`。公式需带 `data-latex` 分组标记，附带的 `math_renderer.py` 已提供这一标记。对于不支持的剪裁、渐变、外部资源或复杂笔画，工具应保留公式组或报告不能处理，不能悄悄删掉内容。按实际输入选择其他矢量工具补足转换。

### SVG 验证

核对普通文字的字符与属性、公式数量及上下标、分式、求和、矩阵。检查字形引用已展开、没有外部依赖或意外位图，语义组仍在；把 SVG 渲染成 PNG，与确认过的稿件对照。另检查最终 PDF 的字体和矢量状态。文件能被浏览器显示不等于已在 PowerPoint 实测，交付说明应区分这两项。

## 2. 只有明确要求原生 PPT 时

用户说“适合 PPT 的 SVG”“SVG 拖入 PPT”“转换为形状后太零散”，仍属于 SVG 请求；先修复 SVG 并交付 SVG/PDF/PNG。不能为了预防 SVG 分组被展开而自行附加 PPTX。用户明确要求原生 PPT 或同时要求两种格式后，才执行以下流程。

- 使用环境中可用的原生 PPT 工作流；若有适用的 `presentations` skill，读取其创作和验证要求。不能绑定某台电脑的运行时路径、LightGCN 的固定元素下标或某个特定图的模块数量。
- 按同一矢量源稿或结构化场景构建：普通文字为原生文本框，节点、矩阵、向量和连线为原生形状，公式为整条表达式的复合自由形状。保留可编辑的内容和颜色。
- 写入真正的 PPT 组合结构与有意义的名字，使整图、模块、对象可以逐级选择和移动。单张 SVG 图片、多个 SVG 图片拼合或一张截图不算原生可编辑 PPT。
- 不要为了 PPT 重设计已经确认的论文图；保持字体角色、相对位置、字号比例、配色和内容。单幅图只需一页，无需额外封面。
- 如需直接处理 OOXML，使用原生 `p:grpSp` / `p:grpSpPr` 和唯一对象 ID。按子对象计算组的紧致边界。组的 `off/ext` 与 `chOff/chExt` 应表达真实坐标映射；不要给每个小组使用整页边界，否则选择和缩放会异常。
- 检查分组层级、文本框、公式及形状数量，重新导入最终 PPTX 并渲染审阅。工具重导入成功和真实 PowerPoint 中操作属于不同证据；如未实测，不宣称已经实测。

## 3. 不混淆 SVG 组和 PPT 组

SVG 的 `<g>` 是源稿层级，不能保证 PowerPoint 的“转换为形状”在所有导入实现中将其映射为原生组合。先通过公式复合路径与语义组减少碎片；用户选择原生 PPT 交付时，才用原生组合保证文件内的组结构。

微软文档介绍了 SVG 插入、转换为形状及转换后的重新组合，没有承诺保留任意 SVG 的嵌套组：

- [在 Microsoft 365 中编辑 SVG](https://support.microsoft.com/en-us/office/graphics-visuals/edit-svg-images-in-microsoft-365)
- [组合或取消组合形状](https://support.microsoft.com/en-us/office/graphics-visuals/group-or-ungroup-shapes-pictures-or-other-objects)

以上兼容处理是本 skill 的执行实践，不是 SIGIR 或其他会议的额外规定。
